# geo_monitor: Динамічний конструктор регіональних патернів

Модуль `geo_monitor` забезпечує безпеку родинних груп шляхом динамічного визначення населених пунктів у радіусі 30 км від їхнього поточного місцезнаходження. Він агрегує дані з бази даних активних локацій та зовнішнього API OpenStreetMap (Overpass), формуючи регулярні вирази для подальшого моніторингу та сповіщень.

## Призначення
Модуль відповідає за створення контекстної географічної карти навколо користувачів. Його головна мета — ідентифікувати всі міста, села та селища, що знаходяться поруч із сім'єю, щоб система могла коректно фільтрувати події або генерувати попередження щодо небезпечних зон у конкретному регіоні.

## Архітектура
Система працює за принципом "запит-кеш-агрегація":
1. **Збір даних**: Отримує координати активних родинних груп з локальної SQLite-бази.
2. **Зовнішній запит**: Виконує асинхронні запити до Overpass API для отримання списку населених пунктів.
3. **Кешування**: Використовує асинхронний кеш у пам'яті з тайм-аутом 1 година, щоб уникнути зайвих запитів до зовнішнього API для одних і тих самих координат.
4. **Формування патерну**: Консолідує отримані назви у регулярний вираз для швидкого пошуку.

## Ключові функції

- `fetch_settlements(lat, lon)` — Асинхронна функція, яка повертає список назв населених пунктів у радіусі 30 км. Використовує кешування для оптимізації продуктивності та блокування для безпеки потоку.
- `_query_overpass(lat, lon)` — Синхронна функція, що виконує HTTP-запит до Overpass API. Фільтрує результати за типами об'єктів (міста, села) та повертає українські або загальні назви.
- `get_all_active_locations(db_path, max_age_hours)` — Функція для отримання актуальних координат родинних груп з бази даних за останні 8 годин (за замовчуванням).
- `_round_coords(lat, lon, precision)` — Утиліта для округлення координат до сітки 1 км, що використовується як ключ для кешування.

## Потік виконання
1. Система сканує базу даних `uav-watcher` на предмет останніх записів про локацію родини.
2. Для кожної унікальної локації (з округленням до 1 км) перевіряється наявність даних у кеші `_settlement_cache`.
3. Якщо кешу немає або він застарів, модуль викликає `_query_overpass` у окремому потоці, щоб не блокувати головний цикл подій.
4. Отриманий список назв зберігається в кеші з міткою часу.
5. Усі отримані назви об'єднуються в єдиний регулярний вираз (regex) для подальшого використання в логіці моніторингу.

## Залежності
- **Бібліотеки Python**: `asyncio`, `sqlite3`, `json`, `re`, `time`, `urllib`.
- **Зовнішні сервіси**: Overpass API (`https://overpass-api.de/api/interpreter`) для отримання географічних даних OpenStreetMap.
- **База даних**: SQLite файл, що містить таблицю з історією локацій родинних груп.
