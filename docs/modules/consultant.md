# Модуль консультанта Sharon (consultant_main)

Сервіс `consultant_main` виступає основним інтерфейсом взаємодії користувача з системою Sharon, надаючи можливості для отримання експертних відповідей на запитання щодо кризових ситуацій та моніторингу поточної обстановки. Він інтегрує знання з бази даних, аналізує поточні загрози та керує історією діалогів, працюючи як централізований хаб для бізнес-логіки прийняття рішень.

## Призначення
Модуль забезпечує безпечний та швидкий доступ до аналізу ситуацій, пов'язаних з моніторингом безпілотних літальних апаратів (БПЛА) та кризових подій. Він трансформує запити користувачів у структуровані відповіді, використовуючи попередньо навчені графи знань та актуальні дані про загрози, дозволяючи операторам швидко оцінювати ризики та отримувати рекомендації.

## Архітектура
Сервіс реалізований як FastAPI-додаток, який запускається на порту 8770. Архітектура базується на асинхронному життєвому циклі (`lifespan`), під час якого ініціалізуються три ключові фонові процеси:
- **Індексація знань:** Завантаження та підготовка бази знань для семантичного пошуку.
- **Спостереження за базою знань:** Моніторинг змін у файлах знань для автоматичного оновлення індексів.
- **Спостереження за ситуацією:** Аналіз зовнішніх джерел (наприклад, alerts.in.ua) для виявлення загроз.
- **Агрегація стрічки:** Підсумовування новинних каналів для формування стислих звітів.

Всі ці процеси працюють у фоновому режимі, забезпечуючи актуальність даних до моменту обробки запиту користувача.

## Ключові функції
- `chat(message, session_id, lang)` — обробляє запит користувача, викликає граф рішень для генерації відповіді та повертає результат із посиланнями на використані джерела знань.
- `session_clear(session_id)` — очищає історію діалогу для вказаної сесії, що дозволяє скинути контекст або змінити мову спілкування.
- `health()` — перевіряє стан сервісу та доступність бази знань, повертаючи кількість завантажених розділів.
- `feed_stats()` — надає статистику по новинній стрічці, включаючи кількість загроз за останню годину та останні підсумки.
- `situation()` — повертає актуальний звіт про поточну ситуацію, отриманий від спостерігача загроз.
- `kb_search(query, top_k)` — виконує семантичний пошук у базі знань за запитом користувача.

## Потік виконання
1. **Ініціалізація:** При запуску сервіс створює директорії для пам'яті та знань, ініціалізує індекс пошуку та запускає фонові потоки для моніторингу.
2. **Обробка запиту:** Користувач надсилає запит через API `/chat`.
3. **Контекстуалізація:** Система збирає контекст з бази знань та поточних даних про загрози.
4. **Генерація:** Граф рішень (`pipeline.graph`) обробляє запит, генерує відповідь на основі контексту та зберігає стан сесії.
5. **Формування відповіді:** Сервіс повертає текст відповіді, ідентифікатор сесії та кількість використаних джерел знань.
6. **Очищення (за потреби):** При виклику `/session/clear` система видаляє збережений контекст сесії з чекпоінтера.

## Залежності
- **Knowledge Base:** Модуль залежить від локальної директорії `knowledge` для зберігання та пошуку документів.
- **Situation Watcher:** Використовує дані з зовнішніх джерел для оновлення контексту загроз.
- **Pipeline Graph:** Залежить від графа рішень для логіки генерації відповідей та управління сесіями.
- **Memory Summarizer:** Потребує доступу до підсумовувача каналів для формування зведених звітів.
- **FastAPI & Uvicorn:** Використовуються як веб-фреймворк та сервер для обслуговування запитів.
