# location_tracker

Модуль забезпечує відстеження останніх відомих координат користувачів для підтримки функції "мертвого перемикача" (dead man's switch) та пошуку укриттів під час надзвичайних ситуацій. Він зберігає геодані у локальній базі SQLite та інтегрується з Telegram-ботом для автоматичної обробки повідомлень з геолокацією.

## Призначення
Модуль слугує критичним компонентом безпеки, дозволяючи рятувальникам або системі автоматично визначати останнє місце перебування людини, яка може бути під завалами або в зоні небезпеки. Він реалізує механізм автоматичного збереження координат при отриманні повідомлень з геоданими та надає функціонал ручного чекіну через команду `/checkin`.

## Архітектура
Модуль використовує легку архітектуру на основі SQLite для зберігання даних без необхідності зовнішніх серверів БД.
- **Слої даних**: Використовує один файл бази даних (`DB_PATH`), спільний з іншими модулями (наприклад, групами родин).
- **Слої логіки**: Містить функції для маніпуляції даними (збереження/читання) та реєстрації обробників подій для Telegram-клієнта.
- **Безпека**: Координати ніколи не записуються у логи у відкритому вигляді, що захищає конфіденційність користувачів.

## Ключові функції

- `_ensure_table()` — ініціалізує таблицю `location_checkins` у базі даних, якщо вона відсутня. Створює структуру для зберігання `user_id`, координат (`lat`, `lon`), адреси та часу оновлення.
- `save_checkin(user_id, lat, lon, address)` — зберігає або оновлює останні відомі координати користувача. Використовує операцію `INSERT OR REPLACE` для гарантії актуальності даних.
- `get_last_location(user_id)` — повертає словник з останніми координатами та адресою користувача або `None`, якщо дані відсутні.
- `register_location_handlers(bot_client, cfg, user_client)` — реєструє обробники подій Telegram-бота:
  - Обробка команди `/checkin` (або `/чекін`) для запуску процесу збереження локації.
  - Автоматичне оброблення повідомлень, що містять геолокацію, з подальшим пошуком найближчих укриттів.

## Потік виконання

1. **Ініціалізація**: При запуску бота викликається `register_location_handlers`, який налаштовує слухачів подій.
2. **Отримання даних**:
   - Користувач надсилає команду `/checkin` або повідомлення з геолокацією.
   - Система ідентифікує відправника та отримує його мовні налаштування.
3. **Збереження**:
   - Викликається `save_checkin` для запису координат у базу даних.
   - Логується факт оновлення без виведення самих координат.
4. **Аналіз та відповідь**:
   - Якщо отримано геолокацію, система автоматично викликає `find_shelters_enhanced` для пошуку укриттів поруч.
   - Результат форматується через `format_shelters_for_chat` та надсилається користувачеві.
   - У разі помилки пошуку відправляється повідомлення про неможливість знайти укриття.

## Залежності

- **Бібліотеки Python**: `sqlite3`, `logging`, `datetime`, `telethon` (для роботи з Telegram API).
- **Внутрішні модулі**:
  - `db.models` — для отримання шляху до бази даних (`DB_PATH`).
  - `bot.i18n` та `bot.lang_store` — для локалізації повідомлень.
  - `shelter_search` — для пошуку та форматування даних про укриття.
- **Базова інфраструктура**:
  - SQLite файл (спільний з іншими модулями проекту).
  - Клієнт Telegram (`bot_client`, `user_client`).
