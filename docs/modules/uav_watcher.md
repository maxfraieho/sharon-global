# Модуль UAV Watcher

Модуль `uav_watcher` забезпечує моніторинг Telegram-каналів на предмет загрози безпілотних літальних апаратів (БПЛА) та ракетних атак для конкретного міста. Він автоматично класифікує повідомлення за допомогою правил ключових слів та штучного інтелекту, фільтрує дублікати та надсилає сповіщення користувачам через Telegram-бота.

## Призначення
Модуль слугує основним джерелом даних про загрози для системи Sharon. Його головна мета — виявляти повідомлення про повітряні тривоги, підліт БПЛА, ракетні атаки та відбої тривоги в реальному часі. Система мінімізує кількість хибних тривог за допомогою багаторівневої фільтрації та забезпечує стабільність сповіщень через механізми затримки (cooldown) та збереження стану.

## Архітектура
Система побудована на асинхронній архітектурі з використанням бібліотеки `Telethon` для роботи з Telegram. Вона включає:
- **Монітор конфігурації**: Перевіряє зміни у файлі налаштувань та дозволяє "гаряче" перезавантаження параметрів міста без перезапуску процесу.
- **Класифікатор**: Двошарова система. Спочатку працює швидкий фільтр на основі регулярних виразів (ключові слова). Якщо результат неочевидний, запит передається до зовнішнього LLM-проксі для аналізу.
- **Менеджер стану**: Зберігає інформацію про активну загрозу та час останніх сповіщень у локальному JSON-файлі, щоб уникнути спаму однаковими повідомленнями.
- **Система сповіщень**: Керує логікою відправки повідомлень, враховуючи пріоритет загрози та часові інтервали між алертами.

## Ключові функції

- `keyword_classify(text, city_keywords)` — швидкий попередній аналіз тексту за ключовими словами. Визначає чітку загрозу, відбій тривоги або передає на аналіз ШІ.
- `ai_classify(text, cfg)` — викликає зовнішній LLM для аналізу двозначних повідомлень, якщо ключові слова не дали однозначного результату.
- `score_proximity(text, city_keywords)` — оцінює ступінь небезпеки (від 1 до 10) на основі наявності слів, що вказують на близькість загрози до міста.
- `hot_reload_city(new_city_cfg)` — динамічно оновлює налаштування моніторингу (місто, регіон, ключові слова) без зупинки сервісу.
- `watch_config_reload()` — фоновий процес, що стежить за змінами у файлах-сигналах для перезавантаження конфігурації або перезапуску бота.
- `_infer_level(text, reason)` — визначає рівень загрози (1-3) на основі тексту повідомлення та причини класифікації.

## Потік виконання

1. **Ініціалізація**: Завантажується конфігурація (`config.json`), налаштовується логірування та перевіряється стан попередніх сповіщень.
2. **Моніторинг**: Бот підключається до Telegram та починає слухати нові повідомлення у підписаних каналах.
3. **Аналіз повідомлення**:
   - Текст перевіряється на наявність слів "відбій" (пріоритетне відключення).
   - Виконується пошук ключових слів міста та регіону.
   - Якщо знайдено ключові слова та шаблони загрози — повідомлення класифікується як загроза миттєво.
   - Якщо ключові слова знайдено, але шаблон неясний — викликається ШІ для уточнення.
   - Якщо ключових слів немає — повідомлення ігнорується.
4. **Оцінка та фільтрація**:
   - Визначається рівень загрози та оцінка близькості.
   - Перевіряється таймер затримки (cooldown): якщо подібна загроза надсилалася нещодавно, нове повідомлення блокується.
5. **Дія**:
   - Якщо загроза підтверджена і не блокується таймером — надсилається сповіщення користувачу.
   - Оновлюється файл стану (`threat_state.json`).
6. **Оновлення конфігурації**: Паралельно процес стежить за файлами-сигналами для оновлення налаштувань міста або перезапуску.

## Залежності

- **Бібліотеки Python**:
  - `telethon` — для взаємодії з Telegram API (клієнт та події).
  - `httpx` — для асинхронних запитів до LLM-проксі.
  - `python-dotenv` — для завантаження змінних оточення.
  - `geo_monitor` — модуль для побудови патернів на основі локацій (імпорт `build_pattern_from_locations`).
- **Зовнішні сервіси**:
  - **Telegram API**: Для отримання повідомлень та відправки сповіщень.
  - **LLM Proxy (Goclaw або інший)**: Для класифікації двозначних повідомлень (потрібен токен та URL).
- **Локальні файли**:
  - `config.json` — основна конфігурація (місто, координати, ключові слова, API-ключі).
  - `data/threat_state.json` — збережений стан активної загрози.
  - `data/.reload_city` — файл-сигнал для перезавантаження налаштувань.
  - `data/.restart_bot` — файл-сигнал для перезапуску бота.
