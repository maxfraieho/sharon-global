# Модуль моніторингу ситуації (situation_watcher)

Модуль `situation_watcher` забезпечує автоматичний моніторинг активних повітряних тривог в Україні через зовнішнє API `alerts.in.ua`. Він працює у фоновому режимі, періодично оновлюючи файл контексту ситуації, який використовується іншими компонентами системи для надання релевантної інформації користувачам.

## Призначення

Основна мета модуля — забезпечити систему актуальними даними про безпекову ситуацію в реальному часі. Це дозволяє:
- Автоматично виявляти активні повітряні тривоги.
- Формувати зведення для користувачів (консультантів) про поточний стан.
- Забезпечувати контекстну підказку в інтерфейсі без необхідності ручного оновлення даних.

Модуль є критичним для функціонування системи попередження та підвищення обізнаності користувачів про загрози.

## Архітектура

Модуль реалізований як фоновий процес (демон), що запускається у окремому потоці (`threading.Thread`). Архітектура базується на циклічному опитуванні зовнішнього API та записі результатів у локальний файл JSON.

**Ключові компоненти:**
- **Опитувач (Poller):** Цикл, що запускається кожні 60 секунд.
- **Клієнт API:** Використовує `httpx` для безпечних запитів до `alerts.in.ua`.
- **Обробник даних:** Фільтрує загальні сповіщення, залишаючи лише "повітряні тривоги", та нормалізує назви регіонів.
- **Сховище контексту:** Локальний файл `situation_context.json`, що містить зведену інформацію та часову мітку.

## Ключові функції

- `start_watcher(project_root)` — Запускає фоновий потік моніторингу. Перевіряє наявність API-токена у конфігурації. Якщо токен відсутній, виводить попередження та припиняє опитування.
- `_fetch_situation(project_root)` — Виконує запит до API `alerts.in.ua`, парсить відповідь, фільтрує активні повітряні тривоги та формує словник з даними (кількість, регіони, зведення).
- `read_situation(project_root)` — Зчитує поточний стан з файлу `situation_context.json`. Повертає порожній рядок, якщо дані застаріли (старіші 5 хвилин), що гарантує актуальність контексту.
- `_build_summary(active, regions)` — Генерує людозчитувану строку-зведення про кількість тривог та перелік регіонів (з обмеженням до 5 регіонів у тексті).
- `_write_context(ctx_path, data)` — Безпечно записує дані у файл через тимчасовий файл та атомарну заміну (atomic replace), запобігаючи пошкодженню даних при збої запису.

## Потік виконання

1. **Ініціалізація:** Викликається `start_watcher`. Потік запускається як демон.
2. **Перевірка конфігурації:** Система перевіряє наявність `alerts_in_ua_token` у `config.json`.
3. **Цикл опитування (кожні 60с):**
   - Виконується запит до `https://api.alerts.in.ua/v1/alerts/active.json`.
   - Отримані дані фільтруються: залишаються лише сповіщення типу `air_raid`.
   - Назви регіонів перекладаються з англійської на українську (наприклад, "Kyivska" → "Київська").
   - Формується зведення (summary) та зберігається у `situation_context.json`.
4. **Читання даних:** Інші модулі викликають `read_situation`. Якщо дані свіжі (менше 5 хв), повертається зведення для відображення користувачу.

## Залежності

- **Зовнішні API:** `alerts.in.ua` (потребує безкоштовного токена реєстрації).
- **Бібліотеки Python:**
  - `httpx` — для асинхронних HTTP-запитів.
  - `threading` — для фонових процесів.
  - `json`, `logging`, `pathlib`, `time` — стандартні бібліотеки.
- **Конфігурація:** Файл `config.json` з полем `alerts_in_ua_token`.
- **Вихідні дані:** Файл `situation_context.json` у корені проєкту.

> **Примітка:** Для коректної роботи необхідно зареєструватися на [alerts.in.ua](https://alerts.in.ua), отримати API-токен та додати його у `config.json`. Без токена модуль працюватиме у режимі "тільки логування" без опитування.
